# 文章互动功能规划

最后更新：2026-09-10

## 目标

在每篇文章末尾增加轻量互动区域，让访客可以直接点赞、留言，并记录每次文章访问。第一版以降低参与门槛和方便张路与读者交流为核心，不建设完整社区系统。

## 已确认的第一版范围

### 评论与回复

- 游客无需注册或主动登录即可评论；底层可以使用匿名身份区分访客。
- 昵称可以留空；留空时显示“匿名”。访客也可以自行填写昵称。
- 评论只支持纯文字，不支持图片、附件、富文本或 Markdown。
- 评论提交后立即生效，不经过审核。
- 访客提交时可以选择“公开评论”或“私密留言”。
- 公开评论及张路的回复对所有人可见。
- 私密留言不向其他访客展示。为了让留言者看到张路的回复，建议定义为“仅张路与原留言者可见”；原留言者通过当前浏览器的匿名身份查看，换设备或清除浏览器数据后可能无法继续查看。
- 第一版每条评论只支持张路回复一次，不做多层对话或楼中楼。

### 点赞

- 文章展示点赞总数。
- 同一匿名访客对同一篇文章只能保留一个点赞，可以取消。
- 匿名身份只能降低普通重复点赞，不能作为严格的实名或防刷机制。

### 阅读记录

- 每次真正打开文章记录一条访问数据；同一人刷新或再次进入会再次计数。
- 每条记录至少保存文章标识和访问时间，可以保存匿名访客标识及不含个人信息的来源信息。
- 不保存原始 IP，不把“阅读次数”表述为精确的独立人数。
- 文章页面可以公开展示阅读次数，后台保留逐条记录用于后续统计。

### 张路的管理能力

- 提供仅张路可以进入的轻量管理页面。
- 可以查看全部公开评论和私密留言。
- 可以回复评论；删除或隐藏评论是否纳入第一版，在实施前最后确认。
- 管理账号信息不在网站公开。

## 平台与访问方案

2026-09-10 已正式确定网站采用“不使用中国大陆基础设施、不办理中国大陆 ICP 备案”的路线。第一版不再使用腾讯云 CloudBase 上海地域作为正式后端，也不把中国大陆服务器或中国大陆 CDN 节点加入生产链路。

现有文章和页面仍暂时部署在 Vercel。部署平台采用先测试再决定的方式：第一选择是 Cloudflare Pages，配合 Workers 与 D1 提供互动接口和数据库；中国香港轻量应用服务器作为中国大陆访问不达标时的后备方案。Vercel继续保留为预览或备用部署。

正式域名仍为 `byzhanglu.com`。先通过 Pages 临时地址和测试子域名完成部署及多运营商访问测试，确认稳定后再修改根域名 DNS、配置 HTTPS 和正式网址。测试期间不购买香港服务器；Cloudflare 访问不达标时，再恢复香港部署并评估普通线路和优选网络。

建议的数据集合：

- `comments`：文章、昵称、正文、公开状态、匿名作者、创建时间、张路回复及回复时间。
- `likes`：文章、匿名访客、点赞时间；文章与访客组合保持唯一。
- `page_views`：文章、匿名访客、访问时间和有限的来源信息。

公开评论查询只能返回公开数据；私密留言只能由张路和原留言者读取。游客只能创建自己的评论、点赞和访问记录，不能修改他人的数据。匿名访客身份改由服务端签发的匿名凭据或等效机制维护，不依赖 CloudBase 匿名身份。

应用数据库不保存原始 IP。托管与安全服务可能产生必要的访问日志，应关闭不必要字段、限制保留时间并防止公开访问。隐私说明需要根据最终平台如实告知互动数据存放方式，并说明收集目的、保存范围和删除方式；选择 Cloudflare 时不得描述为固定存储在中国香港。

## 第一版暂不实施

以下事项明确保留为后续选项，不在第一版中默认加入：

- 评论提交前审核、待审核状态和审核队列。
- Cloudflare Turnstile 或其他验证码。
- 专门的反垃圾、敏感词和内容风控系统。
- 访客注册、手机号、邮箱、微信或第三方账号登录。
- 评论图片、附件、表情包、富文本和 Markdown。
- 楼中楼、多轮对话、访客之间互相回复。
- 评论点赞、举报、排序、置顶和精选。
- 新评论邮件、短信或微信通知。
- 访客跨设备查看私密留言与回复。
- 完整的数据分析后台、导出、自动报表和数据保留策略。
- 将整个网站迁移到中国大陆基础设施、办理 ICP 备案或双站部署。

即使不建设防垃圾系统，第一版仍必须进行基础安全处理：只接受规定长度的纯文字、过滤不可展示内容、避免脚本注入、限制数据字段，并通过数据库安全规则阻止访客读取私密数据或改写他人数据。这属于数据安全底线，不视为额外的审核功能。

## 实施前需要张路准备或确认

1. 创建 Cloudflare Pages 测试项目并完成中国大陆多网络访问验证；未通过前不购买香港服务器。
2. 用于张路管理后台登录的私密邮箱或用户名，不会在网站公开。
3. 确认私密留言是否采用“仅张路与原留言者可见”的方式；如果坚持只有张路能看，则私密留言只能作为单向留言，张路的回复无法在不收集联系方式的情况下送达。
4. 确认公开/私密选项的默认值，建议默认“公开评论”。
5. 确认第一版是否允许张路删除或隐藏已经直接上墙的评论，建议保留这一最低管理能力。
6. 确认昵称和正文长度，建议昵称最多 20 个字符、正文最多 1000 个字符。
7. 确认访客隐私说明，包括数据存储地域、用途、保留时间和删除方式。

## 建议实施顺序

1. 在本地确定数据结构、接口权限、匿名身份和可关闭的功能开关。
2. 在文章末尾实现互动区域，并用本地测试数据完成界面联调。
3. 实现评论、点赞、访问记录接口以及张路的私密管理页面。
4. 创建最终平台的测试环境和数据库；Cloudflare 路线使用 Workers 与 D1，香港后备路线使用同地域接口和数据库。
5. 检查公开/私密权限、重复点赞、逐次访问记录、日志策略、手机端体验和基础安全处理。
6. 通过临时地址和测试子域名完成中国大陆多运营商、分时段访问测试。
7. 由张路确认页面、数据规则和隐私说明后，再决定是否提交、推送、绑定正式域名和上线。
